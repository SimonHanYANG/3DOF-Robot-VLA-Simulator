# 3DOF 推物避障仿真平台实施方案

## 1. 项目概述
本方案旨在构建一个**仿真—数据生成—模型推理—可视化**一体化平台，用于：
- 生成高质量推动轨迹数据，训练视觉语言动作（VLA）模型
- 对 OpenVLA、ACT、π0、π0.5 等主流 VLA 模型进行标准化测试与可视化

**机械臂**：仅 XYZ 三直线轴（无旋转），末端执行器为一推板。  
**任务**：将环境中任意形状物体（球、方块、锥体等）从随机起始位姿**推动**到用户指定的目标位姿，过程需避开**固定障碍物**，且全程不得超出机械臂限位。  
**UI**：提供完整的 3D 交互界面，支持拖拽机械臂、设置任务、加载模型并实时播放推理结果。

## 3. 环境建模与物理仿真

### 3.1 3DOF 机械臂定义
- **关节构型**：三直线滑台 (X, Y, Z)，用 MuJoCo 的 `slide` 关节定义。
- **限位**：X ∈ [-0.5, 0.5] m，Y ∈ [-0.3, 0.3] m，Z ∈ [0.0, 0.4] m（桌面高度以上）。
- **末端工具**：一块固定于 Z 轴末端的矩形推板（尺寸例如 0.04m×0.04m），无旋转，用于推动物体。
- **驱动方式**：位置控制，仿真每步将关节直接设定到目标位置（力矩足够大）。

### 3.2 物体与障碍物
- **物体种类**：球体 (radius=0.02m)，立方体 (0.04m)，锥体 (底面半径 0.02m，高 0.04m)。所有物体初始平放在桌面 (z≈物体半高)。
- **障碍物**：固定位置的圆柱 (r=0.03m, h=0.1m) 或长方体，共 3~5 个，位置硬编码在仿真场景中。
- **摩擦与接触**：设置桌面摩擦系数 μ=0.5，物体与推板之间 μ=0.8，保证推动时物体基本平移（可适当增大物体惯性或约束物体绕 Z 轴旋转）。

### 3.3 坐标系与相机
- 世界坐标系：桌面为 XY 平面，Z 向上。
- 固定相机：布置一个顶视图相机和一个斜 45° 相机，分辨率 224×224（或 256×256），用于渲染 RGB 图像作为模型输入。

## 4. 任务定义与数据生成

### 4.1 任务描述模板
每一条任务数据包含：
- **指令文本**：`“将红色球体推到 (0.20, 0.15)”`（目标位置自动转为文字，可添加颜色、形状属性）
- **初始状态**：随机物体位姿（不与其他物体/障碍物重叠，且在机械臂可达范围内）
- **目标位置**：用户指定的桌面坐标 (x, y)，必须位于限位内且无障碍物占据
- **障碍物布局**：固定不变

### 4.2 专家轨迹生成（数据工厂）
采用 **带推动约束的 RRT 规划算法** 生成无碰撞推动路径：
1. 将任务建模为状态 `(x_obj, y_obj, x_ee, y_ee, z_ee)`。推板与物体接触时满足：  
   `(x_ee, y_ee) = (x_obj, y_obj) + d * (cosθ, sinθ)`，  
   其中 `d` 为推板与物体中心的偏移量，`θ` 为推的方向。为简化，固定推板从物体一侧接触（例如始终从物体‑Y 方向推），则 `x_ee = x_obj, y_ee = y_obj - offset`。
2. 在状态空间中运行 RRT，碰撞检测：
   - 物体包围体不与任何障碍物重叠。
   - 推板包围体不与障碍物、桌面边界发生碰撞。
   - 推板位置始终在限位以内。
3. 对生成的路径进行平滑与稠密采样，得到末端位置序列 `[{x,y,z}_i]`。
4. 在 MuJoCo 中重播此位置序列，微调保证物理可行（若物体脱开，可缩小步长或调整偏移），同时记录：
   - 每步的相机渲染图像
   - 末端绝对位置（动作标签）
   - 物体位姿、语言指令等元数据
5. 存储为结构化数据集（HDF5/RLDS 格式），包含图像、动作、指令。

**数据集规模建议**：10k~50k 条轨迹，覆盖各种物体类型、起始和目标位置的组合。

### 4.3 物理保真度校验
- 每条轨迹重播时验证：物体最终位置与目标位置误差 < 1 cm，全程未碰撞。
- 不合格轨迹丢弃，重新规划。

## 5. VLA 模型集成与推理

### 5.1 统一动作接口
仿真环境向所有模型提供标准化输入输出：
- **输入**（模型观测）：
  - `image`: 224×224×3 RGB 数组（顶视图或拼接双视图）
  - `instruction`: 字符串，如 “push the red cube to (0.20, 0.15)”
- **输出**（动作）：
  - 期望的末端增量位移 `(dx, dy, dz)`，范围限制在 `[-0.02, 0.02]` m
  - 或末端绝对目标位置，由环境适配器转换为增量

### 5.2 各模型适配方案
| 模型      | 加载方式               | 推理特点                           | 适配要点                                      |
|-----------|------------------------|------------------------------------|-----------------------------------------------|
| **OpenVLA** | HuggingFace / 官方权重 | 输入图像+文本，输出离散动作 token  | token 解码为 (dx,dy,dz) 的离散化 bin，再映射回连续量 |
| **ACT**    | 训练自有检查点         | 输入图像+关节状态，预测动作块     | 保留关节状态为末端绝对坐标，使用 Chunk 的前几个动作 |
| **π0 / π0.5** | 官方 API 或权重       | 多模态输入，输出连续动作          | 根据模型输出格式将动作缩放到仿真限位             |

所有模型推理在 Python 后端执行，通过 `torch` / `jax` 加载，每次接收最新的观测图像与指令，返回动作。

### 5.3 推理闭环
```
重置环境 → 模型获得初始图像+指令
loop:
    图像 → 模型推理 → 动作 (dx,dy,dz)
    执行动作，仿真步进
    获取新图像
    检查终止条件（到达目标或超时）
```
- 每次模型推理耗时 < 100ms，满足交互式可视化需求。
- 末端位置不可超出限位，动作执行前裁剪到安全范围。

## 6. UI 详细设计

### 6.1 界面布局
```
┌──────────────────────────────────────────────────────────┐
│  顶部工具栏：[加载模型] [任务设置] [开始推理] [速度▼]    │
├───────────────────────┬──────────────────────────────────┤
│                      │  观测面板                         │
│   3D 主视图          │  - 相机图像实时预览               │
│   (Three.js)         │  - 模型预测动作 (dx,dy,dz)        │
│                      │  - 当前末端位置                   │
│                      │  - 任务指令文本                   │
│                      │                                  │
├───────────────────────┴──────────────────────────────────┤
│  状态栏：推理状态 | 帧率 | 物体距目标误差                  │
└──────────────────────────────────────────────────────────┘
```

### 6.2 核心交互功能
1. **场景漫游**  
   - 鼠标左键旋转视角，右键平移，滚轮缩放。
2. **拖拽机械臂**  
   - 用户可在 3D 视图中直接拖动末端的推板（高亮手柄），沿 XYZ 方向移动。  
   - 拖动时实时更新 MuJoCo 关节位置，并显示当前位置与限位边界（半透明立方体）。
   - 拖动过程中物理仿真暂停（或跟随），松开后机械臂位置生效。
3. **任务设置**  
   - 通过面板选择物体类型（球/方块/锥体），在桌面上点击设置物体初始位置，再次点击设置目标位置（出现标记球）。  
   - 或手动输入坐标数值。  
   - 系统自动校验位置合法（无障碍、不超限位），否则给出红色提示。
4. **模型加载与推理**  
   - 用户通过文件对话框选择模型权重文件（.pt / 目录）。  
   - 点击“开始推理”后，后端重置环境，模型闭环控制，前端实时播放末端与物体运动。  
   - 播放速度可调 (0.5x, 1x, 2x)。  
   - 末端轨迹用渐变曲线绘制，物体轨迹用虚线绘制。
5. **结果反馈**  
   - 成功时绿色提示，失败或碰撞时红色高亮碰撞部位。  
   - 显示最终位置误差。

### 6.3 可视化增强
- 障碍物显示为半透明黄色。
- 限位范围用线框表示。
- 动作预测方向：从末端位置绘制箭头表示 `(dx,dy,dz)`。

## 7. 数据流与消息协议

### 7.1 WebSocket 消息类型
| 消息名              | 方向         | 内容                                        |
|---------------------|--------------|---------------------------------------------|
| `set_ee_pose`       | 前端→后端    | `{x, y, z}` 拖拽末端目标位姿                |
| `set_task`          | 前端→后端    | `{object_type, init_pose, target_pose}`     |
| `load_model`        | 前端→后端    | `{model_name, weight_path}`                 |
| `start_inference`   | 前端→后端    | `{}`                                        |
| `state_update`      | 后端→前端    | `{ee_pose, obj_pose, joints, images, ...}`  |
| `inference_action`  | 后端→前端    | `{action, model_name, timestamp}`           |
| `collision_event`   | 后端→前端    | `{body_A, body_B, position}`                |
| `done`              | 后端→前端    | `{success, final_error}`                    |

### 7.2 帧同步策略
- 仿真步长 0.02s (50Hz)。  
- 每 2 个仿真步（25Hz）向后端发送一次状态更新，包含渲染图像。  
- 推理请求为异步，模型预测完成后动作放入队列，平滑执行。

## 9. 技术栈与依赖

- **仿真物理**：MuJoCo ≥ 3.1, `mujoco-python-viewer`（可选用于调试）
- **后端**：Python 3.10+, FastAPI, `websockets`, `numpy`, `opencv-python`, `Pillow`
- **模型推理**：PyTorch (OpenVLA/ACT), JAX (π0.5), HuggingFace `transformers`
- **前端**：Node.js, React, `@react-three/fiber`, `@react-three/drei`, `three.js`
- **通信**：WebSocket (Socket.IO 或原生)
- **规划库**：`ompl` Python 绑定或自研 RRT
- **数据存储**：HDF5 (`h5py`) 或 `tensorflow_datasets` (RLDS)

## 10. 关键注意事项
- **限位保护**：后端每次执行动作前强制裁剪末端位置到限位内，前端拖拽时也实时约束。
- **障碍物固定**：障碍物位置不随任务变化，简化学习难度，但数据生成仍需检测碰撞。
- **推动稳定性**：适当设置推板与物体的摩擦、物体质量，避免物体倾倒；可在物体 Z 轴加轻微阻尼限制旋转。
- **模型泛化**：在数据集中加入多种颜色/纹理，使 VLA 模型能理解自然语言中的属性。
- **可扩展性**：架构支持后续添加 6DOF 机械臂或更复杂任务，仅需修改场景定义和规划器。

该实施方案提供了从物理仿真、数据工厂、模型连接到交互式 UI 的完整闭环，可直接指导开发团队分阶段落地。
