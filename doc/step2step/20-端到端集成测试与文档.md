#### 测试 3：异常恢复测试
```
1. 推理进行中 → 关闭前端 → 后端推理正常停止（不崩溃）
2. 推理进行中 → 模拟 GPU OOM → 后端发送 error 消息 → 不崩溃
3. WebSocket 断连 → 前端显示断开 → 重连后恢复
4. 发送非法消息 → 后端返回 error → 不崩溃
5. 仿真步进异常 → 推理优雅停止 → 错误信息记录日志
```

#### 测试 4：性能压力测试
```
1. 后端持续运行 1 小时状态广播，检查内存/显存是否稳定
2. 前端连续渲染 30 分钟，检查 FPS 是否稳定在 60fps
3. 批量数据生成 1000 条轨迹，检查管道稳定性
4. 训练运行 1000 步，检查无 OOM 无梯度爆炸
```

### 2. 异常处理完善

#### 2.1 后端异常处理矩阵
| 异常场景 | 处理方式 | 用户感知 |
|----------|----------|----------|
| 模型加载失败 | 返回 error 消息，记录日志 | 红色提示"模型加载失败：xxx" |
| 推理时 GPU OOM | 捕获异常，卸载模型，发送 error | "推理出错：显存不足" |
| WebSocket 断连 | 自动清理连接，广播不受影响 | 前端显示"连接断开" |
| 仿真场景加载失败 | 服务启动失败，退出 | 终端报错 + 日志 |
| 非法动作（如 NaN） | 裁剪为 0 | 前端显示警告 |
| 图像渲染失败 | 发送上一帧图像 | 观测面板暂不变 |
| 任务参数非法 | 返回 error，不修改环境 | 红色提示"位置非法" |
| 磁盘空间不足 | 停止数据生成，发送 warning | 提示"磁盘空间不足" |

#### 2.2 前端异常处理
| 异常场景 | 处理方式 |
|----------|----------|
| WebSocket 连接失败 | 自动重连（指数退避），显示状态 |
| 接收消息格式错误 | 丢弃该消息，打印 console.warn |
| 图像解码失败 | 显示占位图"图像加载失败" |
| 3D 渲染崩溃 | ErrorBoundary 捕获，显示"场景渲染出错" |
| 拖拽超出限位 | 视觉约束 + 松手时裁剪 |

### 3. 性能优化

#### 3.1 后端优化
- **状态广播**：仅在有客户端连接时渲染图像和广播（节省 GPU）
- **图像编码**：使用 libjpeg-turbo 加速 JPEG 编码
- **仿真步进**：批量运行多个仿真步再广播一帧（减少渲染次数）
- **内存管理**：定期清理不再使用的 trajectory 缓存

#### 3.2 前端优化
- **React 组件优化**：对高频更新的组件（Arm, Object3D）使用 `React.memo`
- **R3F 优化**：使用 `instancedMesh` 渲染多个相似物体
- **图像显示**：使用 `requestAnimationFrame` 节流图像刷新率
- **轨迹渲染**：限制轨迹点数量，使用 `BufferGeometry` 直接更新
