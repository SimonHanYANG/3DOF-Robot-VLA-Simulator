## 实现细节

### 1. 仿真服务封装

```python
# backend/services/sim_service.py
import asyncio
import base64
from io import BytesIO
from PIL import Image
from concurrent.futures import ThreadPoolExecutor

class SimService:
    """异步仿真服务，封装 SimController + 状态广播"""

    def __init__(self, scene_path: str):
        self.controller = SimController(scene_path)  # S03 的类
        self.executor = ThreadPoolExecutor(max_workers=2)
        self.broadcast_task: asyncio.Task | None = None
        self.manager = None  # ConnectionManager（由外部注入）

    async def start_broadcast(self, interval: float = 0.04):
        """启动 25Hz 状态广播循环"""
        async def _loop():
            while True:
                state = await self._get_state_async()
                images = await self._render_images_async()
                msg = self._build_state_message(state, images)
                await self.manager.broadcast(msg)
                await asyncio.sleep(interval)
        self.broadcast_task = asyncio.create_task(_loop())

    async def stop_broadcast(self):
        if self.broadcast_task:
            self.broadcast_task.cancel()

    async def handle_set_ee_pose(self, x, y, z):
        """处理前端拖拽：线程池执行仿真操作"""
        loop = asyncio.get_event_loop()
        await loop.run_in_executor(
            self.executor, self.controller.set_ee_pose, x, y, z
        )

    async def handle_set_task(self, object_type, init_pose, target_pose):
        loop = asyncio.get_event_loop()
        await loop.run_in_executor(
            self.executor,
            self.controller.reset,
            object_type, init_pose, target_pose,
        )
```

### 2. 图像编码

仿真控制器渲染的 numpy 数组需编码为可传输的格式：

```python
def encode_image(image_array: np.ndarray, format="JPEG", quality=80) -> str:
    """将 (H,W,3) RGB numpy 数组编码为 base64 JPEG 字符串"""
    pil_img = Image.fromarray(image_array)
    buffer = BytesIO()
    pil_img.save(buffer, format=format, quality=quality)
    return base64.b64encode(buffer.getvalue()).decode("utf-8")
```

- 格式：JPEG（质量 80），在画质和带宽间取得平衡
- 224×224 JPEG 约 5-10KB（base64 后约 7-14KB）
- 两幅图像 + 状态数据约 20KB/帧，25Hz = 500KB/s，局域网可接受

### 3. 任务生命周期管理

采用简单状态机：

```
IDLE → TASK_SET → MODEL_LOADED → INFERRING → DONE
  ↑        ↑                        ↓
  └────────└────────────────────────┘ (出错或手动重置)
```

```python
class TaskState(Enum):
    IDLE = "idle"
    TASK_SET = "task_set"           # 已设置物体和目标
    MODEL_LOADED = "model_loaded"   # 已加载模型权重
    INFERRING = "inferring"         # 正在进行闭环推理
    DONE = "done"                   # 推理结束（成功/失败）
```

    object_type = data["object_type"]
    init_pose = (data["init_pose"]["x"], data["init_pose"]["y"])
    target_pose = (data["target_pose"]["x"], data["target_pose"]["y"])
    await sim_service.handle_set_task(object_type, init_pose, target_pose)

async def route_message(data: dict, websocket: WebSocket):
    msg_type = data.get("type")
    handler = MESSAGE_HANDLERS.get(msg_type)
    if handler is None:
        await websocket.send_json({"type": "error", "message": f"未知消息类型: {msg_type}"})
        return
    await handler(data, websocket)

### 5. 仿真状态消息构建

```python
def _build_state_message(self, state, images):
    return {
        "type": "state_update",
        "ee_pose": state["ee_pose"],
        "obj_pose": {
            "position": state["obj_pose"]["position"],       # (x, y, z)
            "quaternion": state["obj_pose"]["quaternion"],   # (qw, qx, qy, qz)
        },
        "target_pose": state["target_pose"],
        "joint_positions": state["joint_positions"],
        "top_image": encode_image(images["top"]),
        "angle_image": encode_image(images["angle"]),
        "simulation_time": state["time"],
        "task_state": self.task_state.value,
    }
```

注意：`obj_pose` 保留位置和旋转信息，前端在渲染方块/锥体时需要根据 `quaternion` 设置物体朝向。

## 验证标准
- [ ] 连接 WebSocket 后自动收到 25Hz 的 `state_update` 消息
- [ ] `state_update` 中的图像 base64 可解码还原为原始图像
- [ ] 发送 `set_ee_pose` 后，下一帧状态反映新的末端位置
- [ ] 发送 `set_task` 后，仿真正确放置物体到指定位置
- [ ] 多个客户端同时连接时各自独立接收状态流
- [ ] 仿真操作（`set_ee_pose` 等）不阻塞状态广播
- [ ] 断开 WebSocket 后广播循环不受影响（其他客户端继续接收）
- [ ] 状态广播帧率达 25Hz ± 2Hz（可接受范围内）

## 注意事项
- 所有 MuJoCo 操作（渲染、步进）必须在同一线程执行（MuJoCo 非线程安全），使用专用线程池
- 状态广播和消息处理需分离，避免单个消息处理阻塞整个广播循环
- 若无客户端连接，应暂停广播以节省 GPU 渲染资源
- `mj_step` 和 `render` 调用耗时约 2-5ms，25Hz 广播在单线程中有足够余量
