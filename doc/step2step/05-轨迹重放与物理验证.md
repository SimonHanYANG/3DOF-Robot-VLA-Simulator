# S05 — 轨迹重放与物理验证

**状态**：🔴 未开始
**阶段**：二、专家数据生成
**依赖**：S03（仿真控制器）+ S04（RRT 规划器）

## 目标
将 RRT 规划器生成的路径在 MuJoCo 物理引擎中重放，验证物理可行性，对不合格轨迹进行微调或丢弃。

## 前置条件
- S03 完成：`SimController` 可用
- S04 完成：RRT 规划器可输出末端位置序列

## 实现细节

### 1. 轨迹重放流程

```python
def replay_trajectory(sim: SimController, planned_path: list) -> dict:
    """
    在仿真中重放规划路径
    参数:
        planned_path: RRT 输出的 [(x_obj, y_obj, x_ee, y_ee, z_ee), ...]
    返回:
        {
            "success": bool,           # 物理可行
            "final_error": float,      # 终点误差（米）
            "collision_count": int,    # 碰撞次数
            "lost_contact_count": int, # 脱开次数
            "recorded_steps": [...],   # 每步仿真状态
        }
    """
```

重放步骤：
1. `sim.reset()` 将物体放到起始位姿
2. 逐点读取规划路径，将 `(x_ee, y_ee, z_ee)` 通过 `sim.set_ee_pose()` 设为目标位置
3. 每步调用 `sim.step()` 推进仿真（内部执行若干 MuJoCo 步以达到位置控制效果）
4. 记录每一步的仿真状态（物体位姿、末端位姿、碰撞事件）
5. 判断终点误差和过程碰撞

### 2. 物理可行性检查

#### 2.1 脱开检测
- 在每一步计算推板与物体的距离
- 若距离超过阈值（> 0.05m，推板与物体明显分离），记录为脱开事件
- 脱开发生时：物体停止移动，推板空推
- 容忍策略：允许短暂脱开 2-3 步（可自行恢复），超过则判定失败

#### 2.2 碰撞检测
- 利用 `sim.check_collision()` 检测物体是否与障碍物碰撞
- 允许末端执行器轻微接触障碍物（滑动），但物体与障碍物碰撞即为失败

#### 2.3 终点误差
- 轨迹结束时，物体桌面位置 `(x_obj, y_obj)` 与目标 `(x_target, y_target)` 的欧氏距离
- 合格标准：< 0.01m（1cm）

### 3. 微调策略

对于轻微不合格的轨迹（终点误差 1-3cm，或短暂脱开），尝试修复而非直接丢弃：

#### 3.1 步长缩减
- 检测到脱开时，在脱开区间内将步长缩减为原来的 1/2 或 1/4
- 让推板有更多时间"追上"物体

#### 3.2 偏移量微调
- 若推板与物体的接触偏移不合适（过大导致推偏，过小导致碰撞滑脱）
- 尝试 ±0.005m 微调接触偏移量后重新回放

#### 3.3 局部重规划
- 在脱开或碰撞段，保持前后段不变，仅对该段重新运行 RRT（局部重规划）
- 局部重规划的范围：脱开点前 5 步到脱开点后 5 步

### 4. 轨迹数据记录结构

重放成功后，为每条轨迹记录以下数据（为 S06 数据录制做准备）：

## 验证标准
- [ ] 对 100 条 RRT 路径重放，物理合格率 ≥ 95%
- [ ] 脱开检测能正确识别物体与推板分离的情况
- [ ] 微调策略可将 50% 以上的不合格轨迹修复为合格
- [ ] 单条轨迹重放耗时 < 5 秒（满足批量生成需求）
- [ ] 重放后的轨迹记录包含完整的每步数据（为 S06 做准备）
- [ ] 终点误差 < 1cm 且全程物体未碰障碍物

## 注意事项
- 重放时推板的移动速度需合理——太快会"弹开"物体，太慢影响效率。建议 0.005m/仿真步 @ 50Hz（即 0.25m/s），与 S04 稠密采样间距 0.005m 一致
- MuJoCo 的位置控制通过 actuator 的 `ctrl` 实现，可能需要调高 `gain` 参数（如 kp=100）使跟踪更准确
- 对于方块和锥体物体，推动时容易旋转甚至倾倒，可能需要在物体上加 Z 轴旋转阻尼
- 若物体倾倒（物体 Z 轴角度偏离 > 30°），也被判定为失败
