### 2. OpenVLA 格式转换

OpenVLA 使用的数据格式通常为 RLDS（TensorFlow Datasets）或特定的 HuggingFace `datasets` 格式。

#### 目标格式（RLDS 风格，或简化为 HuggingFace datasets）
```python
{
    "image": PIL.Image,              # 观测图像（顶视图，或双视图拼接为 224×448）
    "instruction": str,              # "将红色球体推到 (0.20, 0.15)"
    "action": [dx, dy, dz],          # 增量位移（连续值或离散 bin ID）
    "state": [x_ee, y_ee, z_ee],     # 当前末端位置（可选，取决于模型）
}
```

#### 转换步骤
1. 读取原始 HDF5 轨迹
2. 对每条轨迹的每一步：
   - 取顶视图图像（用 PIL 打开/转换）
   - 计算增量动作：`action = ee_pose[t+1] - ee_pose[t]`
   - 取指令文本
3. 保存为 HuggingFace `datasets.Dataset` 格式（arrow 文件）或 RLDS tfrecord
4. 划分训练集/验证集（90%/10%）

#### 动作离散化（OpenVLA 特定）
OpenVLA 输出的动作是离散 token，需在数据集中预先将连续动作离散化：
- 每个轴 (dx, dy, dz) 分为 N 个 bin（如 N=256），范围 [-0.02, 0.02]m
- 每个 bin 宽度 = 0.04 / 256 ≈ 0.000156m
- 连续值 → bin_id：`bin_id = int((value + 0.02) / 0.04 * 256)`
- 保存时同时保留连续动作和 bin_id

### 3. ACT 格式转换

ACT 需要每步包含：当前图像 + 当前关节状态 + 未来动作序列（action chunk）。

#### 目标格式（HDF5）
```python
# 每个样本
{
    "image": np.ndarray (224, 224, 3),       # 观测图像
    "joint_state": np.ndarray (3,),           # 当前末端位置 (x, y, z)
    "action_chunk": np.ndarray (chunk_len, 3), # 未来 N 步的增量动作
}
```

#### 转换步骤
1. 读取轨迹，每步提取图像和当前末端位置
2. 动作块：第 t 步的 action_chunk = `[action[t], action[t+1], ..., action[t+chunk_len-1]]`
   - `chunk_len` 默认 100（覆盖未来 2 秒 @ 50Hz）
   - 轨迹末尾不足的用零填充
3. 所有样本展平存储（不按轨迹分组）
4. 保存为单个 HDF5 文件（`act_dataset.h5`），包含：
   - `images`: (N, 224, 224, 3) uint8
   - `joint_states`: (N, 3) float32
   - `action_chunks`: (N, chunk_len, 3) float32
   - `instructions`: (N,) 变长字符串

### 4. π0/π0.5 格式转换

π0 系列模型通常使用多模态输入格式，数据以 JSONL 存储。

#### 目标格式（JSONL）
每行一个 JSON 对象：
```json
{
  "image_path": "images/traj_000000_step_000.jpg",
  "instruction": "将红色球体推到 (0.20, 0.15)",
  "state": [0.10, -0.05, 0.02],
  "action": [0.005, 0.003, 0.000],
  "trajectory_id": "traj_000000",
  "step": 0
}
```

#### 转换步骤
1. 将每步图像导出为独立 JPEG 文件到 `images/` 目录
2. 生成 JSONL 文件，每行引用图像路径和对应的状态、动作、指令
3. 同时生成 `train.jsonl` 和 `val.jsonl`

### 5. 数据集划分

- **训练集**：90% 轨迹（按 trajectory_id 划分，同一条轨迹的步不跨分）
- **验证集**：10% 轨迹
- 按轨迹划分而非按步划分，避免数据泄漏
- 分层采样：确保各物体类型在训练/验证集中比例一致

### 6. 数据增强（可选但推荐）

在格式转换时或训练时应用：
- **图像增强**：随机亮度/对比度调整、轻微高斯噪声（模拟真实相机噪声）
- **动作增强**：动作加微小噪声（模拟模型预测不精确性）
- **指令增强**：同一动作对应多种语言表述模板
  - "将红色球体推到 (0.20, 0.15)"
  - "把红色球移动到 x=0.20, y=0.15"
  - "push the red sphere to position (0.20, 0.15)"（如果需要中英双语）

## 注意事项
- 原始 HDF5 中的图像格式可能是 numpy 数组，转换为各格式时注意通道顺序（RGB vs BGR）和数据类型
- OpenVLA 的离散化 bin 数量和范围需与模型 tokenizer 的参数匹配，不同版本的 OpenVLA 可能不同
- ACT 的 chunk_len 影响训练——太长增加计算量，太短"预见性"不足，100 是常用值
- π0 格式需要将图像导出为独立文件，磁盘空间需求较大（10k 轨迹 × 45 步 × 2 相机 ≈ 900k 张图像 × 约 15KB = 约 13.5GB）
- 每种格式的数据集单独存放在 `data/processed/{format}/` 下
