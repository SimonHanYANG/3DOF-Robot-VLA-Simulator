## 实现细节

### 1. HDF5 数据模式设计

#### 数据集层级结构
```
dataset.h5
├── metadata/                    # 全局元数据（属性）
│   ├── "total_trajectories"    : int
│   ├── "creation_date"         : str
│   ├── "object_types"          : ["sphere", "cube", "cone"]
│   ├── "image_size"            : [224, 224]
│   └── "workspace_bounds"      : {...}
├── trajectory_000000/           # 每条轨迹一个 group
│   ├── "instruction"            : str (variable-length UTF-8)
│   ├── "object_type"            : str
│   ├── "object_color"           : str
│   ├── "object_init_pose"       : (2,) float32
│   ├── "target_pose"            : (2,) float32
│   ├── "num_steps"              : int
│   ├── "final_error"            : float32
│   ├── "ee_poses"               : (T, 3) float32   # 末端位置序列
│   ├── "obj_poses"              : (T, 3) float32   # 物体位置序列
│   ├── "top_images"             : (T, 224, 224, 3) uint8
│   ├── "angle_images"           : (T, 224, 224, 3) uint8
│   └── "collision_flags"        : (T,) bool
├── trajectory_000001/
├── ...
```

#### 数据压缩
- 图像数据使用 gzip 压缩（compression="gzip", compression_opts=4）
- 数值数组不压缩（查询速度快）
- 字符串使用变长 UTF-8 存储

### 2. 单条轨迹写入器

```python
class TrajectoryWriter:
    """将重放后的轨迹记录写入 HDF5"""

    def __init__(self, h5_file: h5py.File):
        self.file = h5_file
        self.count = 0

    def write(self, trajectory: dict) -> str:
        """写入一条轨迹，返回 trajectory_id"""
        group_name = f"trajectory_{self.count:06d}"
        grp = self.file.create_group(group_name)
        # 写入标量属性
        grp.attrs["instruction"] = trajectory["instruction"]
        grp.attrs["object_type"] = trajectory["object_type"]
        # ... 写入各数据集
        self.count += 1
        return group_name
```

### 3. 批量生成管道

```python
class DataGenerationPipeline:
    """批量生成轨迹数据集"""

    def __init__(self, sim_controller, planner, writer,
                 total_trajectories=10000,
                 object_types=None,
                 output_path="data/raw/dataset.h5"):
        ...

    def run(self):
        """主循环：生成 → 规划 → 重放 → 验证 → 写入"""
        while self.writer.count < self.total_trajectories:
            # 1. 随机采样任务参数
            task = self._sample_task()
            # 2. 运行 RRT 规划
            path = self.planner.plan(task.start, task.target)
            if path is None:
                continue  # 规划失败，重新采样
            # 3. MuJoCo 重放验证
            result = replay_trajectory(self.sim, path)
            if not result["success"]:
                continue  # 物理不合格，丢弃
            # 4. 写入 HDF5
            self.writer.write(result["recorded_steps"])
            # 5. 进度报告
            self._report_progress()
```

### 4. 任务采样策略

确保数据多样性：
- **物体类型**：均匀分布（球 33% / 方块 33% / 锥体 33%）
- **物体颜色**：每种类型下有 3-5 种颜色变体（红/蓝/绿/黄/白）
- **起始位置**：在机械臂可达范围内均匀随机采样（排除障碍物占据区域）
- **目标位置**：在可达范围内均匀随机采样，且距起始位置 0.1-0.4m（避免太近或太远）
- **障碍物布局**：固定不变（S02 定义的布局），或设计 2-3 组不同布局轮流使用

### 5. 进度报告与断点续传

#### 进度报告
- 每生成 100 条轨迹打印统计：总数/成功率/平均步数/平均终点误差
- 可选用 `tqdm` 显示进度条

#### 断点续传
- 定期（每 500 条）flush HDF5 文件
- 记录已生成的轨迹数量，允许中断后从上次位置继续
- 通过检查 HDF5 中已有的 trajectory group 数量判断断点

## 注意事项
- Windows 下 HDF5 文件路径需注意编码问题，使用 `pathlib.Path`
- 大数据集（> 50k 条）的 HDF5 文件可能达到数十 GB，确保磁盘空间充足
- 读取数据时使用 `with h5py.File(..., "r")` 避免文件损坏
- 未来若要兼容 RLDS 格式（TensorFlow Datasets），可在本步骤预留数据导出接口，正式格式转换在 S13 进行
- 批量生成耗时较长（数小时到数天），建议在服务器上运行并做好断点续传
